Chief of Staff Agent

Sabrina — Install & Test Guide

Cowork + Apps Script + Gmail add-on + Google Workspace. Use this for every new install. Gmail-based accounts only. Updated 2026-10-20 from the live script (16 files).

Overview

What Sabrina Does

Sabrina is a chief-of-staff agent. She watches for work you give her. She does the part she can do alone. She comes back to you only for the part that needs a human decision.

Taking work in

  • Three ways in. Put an event on your Task Calendar with [Agent] in the title. Label an email Agent. Email or forward to her alias.
  • Gmail side panel. Open any email. Tap Send to Sabrina. Add a direction, pick a lane, and mark it heavy if it should run overnight.
  • Attachments. Cowork cannot read Gmail attachments. The script copies each real attachment to Drive. Cowork reads it from there.

Doing the work

  • Does the doable part first. She drafts, pulls context, or works the task before she asks you anything.
  • Heavy jobs run overnight. Reply heavy, tick the box in the panel, or let Cowork decide. The job waits for the 10pm to 4am window.
  • Lanes. Every job has a lane, one area of your work. Each email ends with a short In play list for that lane.
  • Meetings become tickets. After a call she reads the transcript and files one ticket per action item that belongs to you. Claude can do it tickets run on a later pass. Needs you tickets are emailed to you. She sends no recap.
  • One living Client Update doc per client. It shows what closed, what is open, and what blocks work. It attaches to the recurring invite.
  • Ideas. A job of class idea gets one nurture question about every four days. Reply mature to turn it into real work, or kill to end it.

Talking to you

  • One short email per job. It fits one phone screen. The subject starts with the time it costs you, such as [15 min].
  • Reply like to a colleague. Plain words work. So do these control words: close, snooze 5d, waiting on <name>, confirm <id>, heavy, run now. The panel buttons do the same things.
  • Follows up until done. She chases every day or two. She checks completion herself. A job closes only when every deliverable is verified, confirmed by you, or waived.
  • Dashboard. A web page shows work by lane: needs you, stalled, waiting on others, with Sabrina. Every email links to it.

Never quiet

  • Dead-letter guard. A failed job that never reached you gets an email.
  • Silent-parking guard. A job parked with nothing to say goes back to the queue.
What this page is not: a list of function names. The rest of this guide covers what you install and how to prove it works.
Stack & Order

The Stack

PieceJob it does
Job Board (Google Sheet)The only memory the system has. Five tabs: jobs (17 columns), history, deliverables, attachments, projects. Every job, status and history entry is a row.
Google Apps Script16 files. Watches the calendar and Gmail, writes job rows, sends every email from the agent address, chases and verifies, and runs the guards. It never does the work.
GmailTrigger surface (labels, direct email) and reply surface. Must be Gmail or Google Workspace. Not Microsoft 365.
Gmail add-onThe Sabrina side panel. Part of the same Apps Script project. Installed as a test deployment, one per person.
Dashboard (web app)Part of the same project. Deployed as a web app. Its URL goes in the script config and in every email footer.
Google CalendarA Task Calendar, separate from real events. Cowork also reads the main calendar once per client to find the recurring meeting.
Google Drive and DocsOne Client Update doc per client. A folder of copied attachments. Meeting transcripts land here for Cowork.
CoworkThe worker. Each hour it claims a queued row, does the work, and writes the result to the row.
Know before you start: the lane names and the install identifiers are still inside the code. The wizard gives copy blocks for them. Moving them to Script Properties is open work.

Why the Order Matters

Do the Sheet before the Apps Script. Copy the Job Board first so you have its real ID. Then copy the script and point it at that ID from the start. A placeholder ID caused the wrong-ID bug and the column-mismatch bug on past installs.

Order:

  1. Alias, Job Board, Task Calendar, Client Update template
  2. Apps Script copy, time zone, identifiers, lanes
  3. Gmail labels
  4. Authorize and send the first test email
  5. Dashboard deployment and Gmail add-on
  6. Timers, then mail filters
  7. Cowork: connectors, skill, scheduled task
  8. Test end to end
Step 3 of 4

Installation

Use the setup wizard in the setup-wizards repo, folder sabrina. It keeps your values and fills them into each step. The steps below are the same list. Source: github.com/keyona-rerev/setup-wizards/tree/main/sabrina.

You need the Job Board template, the Apps Script template and the Client Update doc template from ReRev Labs.

  1. Create the send-as alias (sabrina@domain.com) on the Google account. Confirm it in Gmail → Settings → Accounts → Send mail as.
    📸Screenshot here: Send mail as, with the alias listed and no Verify link.
  2. Copy the Job Board template. Name it for the install. Save the Sheet ID.
    Check that the jobs tab has 17 columns in row 1. Column 15 is time_estimate, 16 is run_after, 17 is lane. The template has no installs or wizard_template tab.
  3. Create the Task Calendar. Save its Calendar ID (ends in @group.calendar.google.com).
  4. Copy the Client Update doc template. Keep it private. Save its doc ID.
  5. Copy the Apps Script project. In appsscript.json, set timeZone to the client's time zone.
    Deadlines, nudges and the overnight window all follow this setting. The template holds no ReRev Labs values.
  6. In Project Settings → Script Properties, set BOARD_ID, OWNER and SEND_AS (required). Set AGENT_NAME to the name the client chose (default Sabrina; it shows in the add-on, Dashboard and email sender name). Optionally set ALLOWLIST, CALENDAR_NAME, DASHBOARD_URL, HEAVY_START_HOUR (default 22) and HEAVY_END_HOUR (default 4). Run checkConfig.
    No code is edited. The overnight window is in the script time zone.
  7. On the Job Board lanes tab, add one row per lane (lane, group, aliases, domains). Delete the example rows. Run refreshLanes. If you skip this, the Dashboard shows no lanes.
  8. Run setupBoard (creates missing tabs, the Agent label and the Task Calendar). Then create one Gmail label per lane. Each lane label must match the lane name exactly.
  9. Run selfTest. Authorize with the Google account. The warning screen is normal. An email must arrive from the alias with a [5 min] subject tag.
  10. Deploy the Dashboard: Deploy → New deployment → Web app. Execute as Me. Access: Only myself. Name it Sabrina Dashboard v1. Copy the /exec URL into the DASHBOARD_URL Script Property.
    After any code change use Manage deployments → Edit → New version. A new deployment makes a new URL.
  11. Install the Gmail add-on: Deploy → Test deployments → Gmail add-on → Install. Reload Gmail. The Sabrina icon shows in the side panel. Each person installs it from their own copy.
  12. Run installTriggers once. The Triggers page lists 8 triggers.
  13. Make a Gmail filter on the main account and on every extra inbox: To the alias → apply label Agent. Add every sending address to ALLOWLIST.
  14. Confirm the meeting transcript source. Google Meet with Gemini notes needs nothing extra. Any other note-taker needs one added step that lands transcripts in one Drive folder.
  15. In Cowork, connect Google Drive, Docs, Calendar and Sheets.
  16. Build the Cowork runtime skill. The setup wizard's Download finished skill button fills every placeholder for you (agent name, Sheet ID, Calendar ID, template ID, alias, allowlist). By hand, fill its identifiers table: Sheet ID, Task Calendar ID and name, Client Update template ID, owner email, alias, time zone, lanes. Zip it. Upload it at Settings → Customize → Skills.
  17. Create the Cowork scheduled task: Active, hourly, pointed at the skill.
Step 4 of 4

Run the Test

Check off each item when you confirm it. Do not move on until the current item is confirmed. Run the tests on a weekday.

0 of 16 confirmed
  • Run selfTest. An email arrives from the alias. The subject starts with [5 min]. The footer has a Dashboard button and a Job Board link. Both open.
  • Open Triggers. It lists 8: watchCalendar (15 min), watchGmailLabel (5), sendPending (5), watchReplies (5), watchdog (1 h), verifyDeliverables (2 h), nudgeSweep (daily), releaseHeavyJobs (15 min).
  • Run smokeTestSetup, then verifyDeliverables, then smokeTestNudge, then smokeTestCleanup. Deliverable d1 becomes verified. A nudge arrives as a reply on the same thread. d2 is waived at cleanup.
  • Run a Cowork smoke test. Confirm all three: (1) read a cell on the Job Board, (2) write a cell on the Job Board, (3) answer a question only account memory can answer, such as a saved writing-style preference.
  • Create one [Agent] event on the Task Calendar with Lane: <lane> in the description. The watcher writes a queued row with the lane in column 17.
  • Cowork claims and works the row on its next hourly run. The status goes claimed, then awaiting_human.
  • Apps Script delivers the email from the alias. It is short and fits one phone screen. It ends with an In play list for the lane.
  • Send an email from the owner address to the alias. The filter applies the Agent label. A job row appears. Then send one from an address not on the allowlist. You get a rejected-message notice and no job starts.
  • Open any email in Gmail. The Sabrina panel shows a form. Send it to Sabrina with a direction and a lane. A job row appears with that lane. Tap Snooze 2d on the job card. The panel home shows four numbers.
  • Open the Dashboard URL. It shows the client's lanes and no other business's lanes. The job from the calendar test sits in the right lane.
  • Forward an email with a PDF to the alias. The PDF is in Drive in Task Agent - Attachments, in a folder for the job. One row on the attachments tab names it.
  • Reply with these words on an open job, one at a time: snooze 2d, waiting on Test Person, heavy, run now, close. After heavy, run_after is at or after 10pm local time, unless it is already between 10pm and 4am.
  • Add a test row with status failed and no pending_email. Run inspectDeadLetters. It lists the row. The next hourly watchdog emails you about it. Delete the row.
  • Add a test row with status awaiting_human and no pending_email. After 30 minutes and one send run, it returns to queued. Delete the row.
  • Run one real call transcript through the meeting flow. The board shows one meeting_item row per action item. Items Claude can do are queued. Items for the owner are awaiting_human, each with an email. No recap is sent.
  • The Client Update doc exists and is private. An approval ticket asks the owner to reply yes. After yes, the doc attaches to the recurring invite. The client got no calendar or share email you did not expect.
Not covered by this test: the Idea Nurture flow, the build job class, and the track and untrack project verbs. Test them on first use.
