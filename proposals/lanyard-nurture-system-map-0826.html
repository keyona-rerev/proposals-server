The architecture

Two systems that never talk to each other. Apps Script runs on a clock and does only deterministic work. Cowork runs when it runs and does the reading. The Sheet is the handoff, so if either side is down the other keeps working and picks the rows back up later.

Threading by archetype

A Gmail reply inherits its subject line, so threaded and fresh subjects are mutually exclusive. This is set per sequence in Config.gs, not per email.

ArchetypeThreadingWhy
Ready NowThreadedTwo or three touches over a short window. Same conversation keeps the momentum from the call.
Frustrated SwitcherFresh subjectsThey forward internally while evaluating. Each email has to stand on its own as a forwardable artifact.
Complex or ContingentFresh subjectsHorizon is months. A Re: chain with three week gaps reads stale.
No UrgencyFresh subjectsLongest horizon, lowest engagement. An unanswered Re: chain reads as nagging.

What actually breaks

Reply detection missing one

The only genuinely bad outcome. Someone replies yes and still gets a scripted email. Runs before every send, on every pass.

Double sends

Manual run plus the daily trigger, or a send that succeeds before the counter write fails. Guard on last_sent_at being today.

Date math

Weekends, month boundaries, and script timezone not matching hers. Not dangerous, just sloppy.

Wrong sender on port

Apps Script triggers run as whoever installed them. If she never installs her own, mail goes out from your address.

Test plan

You cannot test this by booking and waiting, the sequences run over weeks. Seed rows and backdate instead. Four passes, about twenty minutes, no framework.
